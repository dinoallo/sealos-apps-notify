# Grafana ContactPoint 直连 notify 字段映射说明

本文说明 Grafana 告警通过 `GrafanaContactPoint` 直连 `sealos-notify` 时，数据从哪里来、如何映射、最终 `notify` 收到什么结构。

目标链路：

```text
Grafana alert notification data
  -> GrafanaContactPoint webhook custom payload template
  -> POST /api/v1/notifications
  -> notify SendNotificationRequest
  -> feishu_app delivery task
  -> Feishu app message + urgent notification
```

这里不使用 `/api/v1/grafana/webhook` 中间转换接口。Grafana ContactPoint 自己生成 `notify` 原生 JSON。

## 1. Grafana 原始通知数据结构

Grafana webhook contact point 在发送通知时，模板中可以访问一份 notification data。它不是普通 HTTP 请求体，而是 Grafana 模板上下文。下面用 `jsonc` 描述我们关心的字段。

```jsonc
{
  // 当前通知组状态。
  // 常见值：
  // - "firing": 组内至少有一条告警正在触发
  // - "resolved": 组内告警恢复
  "Status": "firing",

  // 这个通知组里的所有告警实例。
  // 在 Grafana 模板里访问方式是 .Alerts。
  "Alerts": [
    {
      // 单条告警的状态，通常是 "firing" 或 "resolved"。
      "Status": "firing",

      // 单条告警的 label 集合。
      // 来自 Grafana alert rule 的 labels，再加上 Grafana 自动补充的 labels。
      "Labels": {
        "alertname": "Grafana HA Test V2 Transition Alert",
        "grafana_folder": "HA Test Alerts V2",
        "severity": "test",
        "test_id": "ha-test-v2-transition"
      },

      // 单条告警的 annotation 集合。
      // 来自 Grafana alert rule 的 annotations。
      "Annotations": {
        "summary": "Grafana direct notify 飞书加急测试",
        "description": "当前阶段为 Firing，用于验证 Grafana ContactPoint 直连 sealos-notify /api/v1/notifications。"
      },

      // Grafana 为单条告警生成的稳定指纹。
      // 同一条告警从 firing 到 resolved 通常保持一致。
      // 我们用它参与生成 notify 的 idempotencyKey。
      "Fingerprint": "400a50a6a9c85052",

      // 告警开始时间。
      // 模板中可以访问，但当前 contact point 没有映射到 notify。
      "StartsAt": "2026-07-01T09:19:40Z",

      // 告警恢复时间。
      // firing 时通常为空或零值，resolved 时有值。
      // 当前 contact point 没有映射到 notify。
      "EndsAt": "0001-01-01T00:00:00Z",

      // Grafana 生成的告警详情链接。
      // 当前 contact point 没有直接使用单条 alert 的 GeneratorURL。
      "GeneratorURL": "http://localhost:3000/alerting/grafana/...",

      // Dashboard URL，只有规则关联 dashboard 时才有。
      // 当前 contact point 没有映射。
      "DashboardURL": "",

      // Panel URL，只有规则关联 panel 时才有。
      // 当前 contact point 没有映射。
      "PanelURL": "",

      // Silence URL，可用于快速静默该告警。
      // 当前 contact point 没有映射。
      "SilenceURL": "",

      // Values 是表达式/查询结果值。
      // 当前 contact point 没有映射。
      "Values": {
        "A": 2,
        "C": 1
      }
    }
  ],

  // 通知组内所有告警共同拥有的 labels。
  // 我们从这里取 alertname、severity。
  "CommonLabels": {
    "alertname": "Grafana HA Test V2 Transition Alert",
    "grafana_folder": "HA Test Alerts V2",
    "severity": "test",
    "test_id": "ha-test-v2-transition"
  },

  // 通知组内所有告警共同拥有的 annotations。
  // 我们从这里取 summary、description。
  "CommonAnnotations": {
    "summary": "Grafana direct notify 飞书加急测试",
    "description": "当前阶段为 Firing，用于验证 Grafana ContactPoint 直连 sealos-notify /api/v1/notifications。"
  },

  // 当前 receiver/contact point 名。
  "Receiver": "ha-test-feishu",

  // Grafana Alertmanager 的通知组 key。
  // 用于描述本次通知组的 grouping 结果。
  // 我们把它传给 notify params，方便排查路由和分组。
  "GroupKey": "{}/{__grafana_autogenerated__=\"true\"}/{__grafana_receiver__=\"ha-test-feishu\"}/{__grafana_route_settings_hash__=\"5422339a4cf06bd1\"}:{alertname=\"Grafana HA Test V2 Transition Alert\", grafana_folder=\"HA Test Alerts V2\", test_id=\"ha-test-v2-transition\"}",

  // Grafana 外部访问地址。
  // 当前 53 集群实际值是 http://localhost:3000/，说明 Grafana external URL 还需要配置成真实可访问地址。
  "ExternalURL": "http://localhost:3000/",

  // ContactPoint payload.vars 里定义并通过 valuesFrom 注入的变量。
  // 这不是 Grafana 告警原生字段，是 contact point 自己的变量区。
  "Vars": {
    "feishu_open_id": "ou_7fb2f2969dc389a1478aedeb680675f3"
  }
}
```

## 2. ContactPoint 配置结构

当前直连方案的关键配置如下。示例来自 `deploy/grafana/contactpoint.yaml`，53 集群测试时实际资源名是 `vm/ha-test-feishu`，但映射逻辑一致。

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: sealos-notify-contactpoint
  namespace: grafana
type: Opaque
stringData:
  # notify API 鉴权 token。
  # Grafana 会把它注入 authorization_credentials。
  # 配合 authorization_scheme: Bearer 后，最终 HTTP header 是：
  # Authorization: Bearer grafana:grafana
  bearer-token: grafana:grafana

  # 飞书接收人的 open_id。
  # Grafana 会把它注入 payload.vars.feishu_open_id。
  feishu-open-id: ou_7fb2f2969dc389a1478aedeb680675f3
---
apiVersion: grafana.integreatly.org/v1beta1
kind: GrafanaContactPoint
metadata:
  # Kubernetes 资源名。
  name: sealos-notify-feishu-urgent
  namespace: grafana
spec:
  # 不允许跨 namespace 引用。
  allowCrossNamespaceImport: false

  # 选择要同步到哪些 Grafana 实例。
  instanceSelector:
    matchLabels:
      dashboards: grafana

  # Grafana 内部 receiver/contact point 名。
  # AlertRuleGroup.notificationSettings.receiver 必须指向这个名字。
  name: sealos-notify-feishu-urgent

  # Grafana Operator 重新同步该 ContactPoint 到 Grafana 实例的周期。
  resyncPeriod: 10m0s

  settings:
    # 直连 notify 原生通知创建接口。
    # 注意这里不是 /api/v1/grafana/webhook。
    url: http://sealos-notify.ns-admin.svc.cluster.local:8080/api/v1/notifications

    # notify 创建通知接口使用 POST。
    httpMethod: POST

    # Grafana webhook 鉴权 scheme。
    # 和 authorization_credentials 组合成 Authorization header。
    authorization_scheme: Bearer

    payload:
      # Grafana webhook custom payload template。
      # 这个模板必须渲染出 notify /api/v1/notifications 能接收的 JSON。
      template: |
        {{- $fingerprint := .GroupKey -}}
        {{- if gt (len .Alerts) 0 -}}
          {{- $fingerprint = (index .Alerts 0).Fingerprint -}}
        {{- end -}}
        {{ coll.Dict
          "idempotencyKey" (printf "grafana-%s-%s" .Status $fingerprint)
          "channels" (coll.Dict
            "feishu_app" (coll.Dict
              "template" "feishu-grafana-alert"
              "params" (coll.Dict
                "status" .Status
                "alertname" .CommonLabels.alertname
                "severity" .CommonLabels.severity
                "summary" .CommonAnnotations.summary
                "description" .CommonAnnotations.description
                "groupKey" .GroupKey
                "externalURL" .ExternalURL
              )
            )
          )
          "recipients" (coll.Slice
            (coll.Dict
              "type" "feishu_user_id"
              "value" .Vars.feishu_open_id
            )
          )
        | data.ToJSON }}

      vars:
        # 先定义为空值，再由 valuesFrom 从 Secret 注入真实值。
        feishu_open_id: ""

  # Grafana contact point 类型。
  type: webhook

  valuesFrom:
    - targetPath: authorization_credentials
      valueFrom:
        secretKeyRef:
          name: sealos-notify-contactpoint
          key: bearer-token

    - targetPath: payload.vars.feishu_open_id
      valueFrom:
        secretKeyRef:
          name: sealos-notify-contactpoint
          key: feishu-open-id
```

## 3. ContactPoint 模板映射规则

### 3.1 幂等 key 生成

模板：

```gotemplate
{{- $fingerprint := .GroupKey -}}
{{- if gt (len .Alerts) 0 -}}
  {{- $fingerprint = (index .Alerts 0).Fingerprint -}}
{{- end -}}
```

生成策略：

```jsonc
{
  // 默认使用 GroupKey 作为 fingerprint 兜底。
  // 如果 .Alerts 至少有一条，则使用第一条 alert 的 Fingerprint。
  // 原因：
  // - Fingerprint 比 GroupKey 更贴近单条告警实例
  // - 同一条告警 firing/resolved 通常 fingerprint 一致
  // - .Alerts 为空时不会模板报错
  "fingerprint": "400a50a6a9c85052"
}
```

模板：

```gotemplate
"idempotencyKey" (printf "grafana-%s-%s" .Status $fingerprint)
```

生成结果：

```jsonc
{
  // notify 用它做请求幂等。
  // 当前策略是 grafana-<状态>-<告警指纹>。
  // firing 和 resolved 会生成不同 key，因此恢复通知不会被 firing 通知的幂等记录吃掉。
  "idempotencyKey": "grafana-firing-400a50a6a9c85052"
}
```

注意：如果希望 Grafana 的 repeat notification 每次都真正发送，不能只用 `status + fingerprint`，否则同一状态的重复通知会被 notify 幂等逻辑去重。当前策略更偏向“同一状态只创建一次，避免重复轰炸”。

### 3.2 channels 映射

模板：

```gotemplate
"channels" (coll.Dict
  "feishu_app" (coll.Dict
    "template" "feishu-grafana-alert"
    "params" ...
  )
)
```

生成结果：

```jsonc
{
  "channels": {
    // notify channel 名。
    // notify 配置中 feishu_app 会指向 provider feishu-app-urgent。
    "feishu_app": {
      // notify 数据库中的模板名。
      // 该模板 channel 必须也是 feishu_app。
      "template": "feishu-grafana-alert",

      // 模板渲染参数。
      // notify 会把 params 传给 feishu-grafana-alert 模板。
      "params": {}
    }
  }
}
```

### 3.3 params 映射

模板：

```gotemplate
"params" (coll.Dict
  "status" .Status
  "alertname" .CommonLabels.alertname
  "severity" .CommonLabels.severity
  "summary" .CommonAnnotations.summary
  "description" .CommonAnnotations.description
  "groupKey" .GroupKey
  "externalURL" .ExternalURL
)
```

字段映射：

```jsonc
{
  "params": {
    // 来自 Grafana .Status。
    // 传给 notify 模板后，可渲染为 [Grafana firing] 或 [Grafana resolved]。
    "status": "firing",

    // 来自 Grafana .CommonLabels.alertname。
    // Grafana-managed alert 中通常是规则 title。
    "alertname": "Grafana HA Test V2 Transition Alert",

    // 来自 Grafana .CommonLabels.severity。
    // 对应 alert rule labels.severity。
    "severity": "test",

    // 来自 Grafana .CommonAnnotations.summary。
    // 对应 alert rule annotations.summary。
    "summary": "Grafana direct notify 飞书加急测试",

    // 来自 Grafana .CommonAnnotations.description。
    // 对应 alert rule annotations.description。
    "description": "当前阶段为 Firing，用于验证 Grafana ContactPoint 直连 sealos-notify /api/v1/notifications。",

    // 来自 Grafana .GroupKey。
    // 主要用于排查分组、路由、receiver hash。
    // 当前 notify 模板不一定展示它，但保留在 delivery task 的 templateParams 里。
    "groupKey": "{}/{__grafana_autogenerated__=\"true\"}/{__grafana_receiver__=\"ha-test-feishu\"}/{__grafana_route_settings_hash__=\"5422339a4cf06bd1\"}:{alertname=\"Grafana HA Test V2 Transition Alert\", grafana_folder=\"HA Test Alerts V2\", test_id=\"ha-test-v2-transition\"}",

    // 来自 Grafana .ExternalURL。
    // 如果 Grafana 没配置 external URL，可能会是 http://localhost:3000/。
    "externalURL": "http://localhost:3000/"
  }
}
```

### 3.4 recipients 映射

模板：

```gotemplate
"recipients" (coll.Slice
  (coll.Dict
    "type" "feishu_user_id"
    "value" .Vars.feishu_open_id
  )
)
```

生成结果：

```jsonc
{
  "recipients": [
    {
      // notify recipient 类型。
      // feishu_app channel 支持 feishu_user_id。
      "type": "feishu_user_id",

      // 来自 .Vars.feishu_open_id。
      // .Vars.feishu_open_id 由 Secret sealos-notify-contactpoint 的 feishu-open-id 注入。
      // 由于 notify provider 配置 receiveIdType=open_id，这里必须是飞书 open_id，即 ou_...。
      "value": "ou_7fb2f2969dc389a1478aedeb680675f3"
    }
  ]
}
```

### 3.5 为什么用 coll.Dict 和 data.ToJSON

模板最后一行：

```gotemplate
| data.ToJSON
```

作用是把 `coll.Dict` 生成的对象安全序列化成 JSON。

不要手写 JSON 字符串：

```gotemplate
{
  "summary": "{{ .CommonAnnotations.summary }}"
}
```

原因是 annotation 里可能包含：

```jsonc
{
  // 换行
  "summary": "line1\nline2",

  // 双引号
  "description": "service \"api\" failed",

  // 反斜杠
  "path": "C:\\tmp\\file"
}
```

手写 JSON 很容易因为转义不完整导致 notify 收到非法 JSON。`data.ToJSON` 会自动处理转义。

## 4. 映射后的 notify 请求结构

Grafana 渲染 `payload.template` 后，真正发送给 notify 的 HTTP 请求如下：

```http
POST /api/v1/notifications HTTP/1.1
Host: sealos-notify.ns-admin.svc.cluster.local:8080
User-Agent: Grafana
Content-Type: application/json
Authorization: Bearer grafana:grafana
```

请求体：

```jsonc
{
  // notify 幂等 key。
  // 相同 idempotencyKey 的请求会被 notify 当成同一请求处理。
  "idempotencyKey": "grafana-firing-400a50a6a9c85052",

  "channels": {
    // 发送到 notify 的 feishu_app channel。
    "feishu_app": {
      // notify 模板名。
      "template": "feishu-grafana-alert",

      // 模板参数，供 notify 渲染飞书消息。
      "params": {
        "status": "firing",
        "alertname": "Grafana HA Test V2 Transition Alert",
        "severity": "test",
        "summary": "Grafana direct notify 飞书加急测试",
        "description": "当前阶段为 Firing，用于验证 Grafana ContactPoint 直连 sealos-notify /api/v1/notifications。",
        "groupKey": "{}/{__grafana_autogenerated__=\"true\"}/{__grafana_receiver__=\"ha-test-feishu\"}/{__grafana_route_settings_hash__=\"5422339a4cf06bd1\"}:{alertname=\"Grafana HA Test V2 Transition Alert\", grafana_folder=\"HA Test Alerts V2\", test_id=\"ha-test-v2-transition\"}",
        "externalURL": "http://localhost:3000/"
      }
    }
  },

  "recipients": [
    {
      // recipient identifier type。
      "type": "feishu_user_id",

      // 飞书 open_id。
      "value": "ou_7fb2f2969dc389a1478aedeb680675f3"
    }
  ]
}
```

## 5. notify 服务端接收结构

notify 的 `/api/v1/notifications` 对应 Go 结构是 `engine.SendNotificationRequest`。

```jsonc
{
  // 必填。
  // notify 用来做幂等创建。
  // 如果数据库里已经有相同 idempotencyKey 的 notification，notify 会返回已有记录，不再重复创建 delivery tasks。
  "idempotencyKey": "grafana-firing-400a50a6a9c85052",

  // 必填。
  // key 是 notify channel 名，例如 feishu_app、email、sms。
  // value 是该 channel 的模板和模板参数。
  "channels": {
    "feishu_app": {
      // 必填。
      // notify 会按 name 查 templates 表。
      // 模板的 channel 必须与这里的 channel 匹配。
      "template": "feishu-grafana-alert",

      // 可选。
      // Go 类型是 map[string]string。
      // 这些值会写入 delivery_tasks.template_params，并用于模板渲染。
      "params": {
        "status": "firing",
        "alertname": "Grafana HA Test V2 Transition Alert",
        "severity": "test",
        "summary": "Grafana direct notify 飞书加急测试",
        "description": "当前阶段为 Firing，用于验证 Grafana ContactPoint 直连 sealos-notify /api/v1/notifications。",
        "groupKey": "{...}",
        "externalURL": "http://localhost:3000/"
      }
    }
  },

  // 必填。
  // notify 会为每个 recipient 创建 notification_recipients 记录。
  // 然后根据 recipient.type 是否被 channel 支持，生成 delivery_tasks。
  "recipients": [
    {
      // 必填。
      // feishu_app 支持 feishu_user_id 和 email。
      // 当前用 feishu_user_id。
      "type": "feishu_user_id",

      // 必填。
      // 具体接收地址。
      // 对 feishu_app + receiveIdType=open_id 来说，这里是飞书 open_id。
      "value": "ou_7fb2f2969dc389a1478aedeb680675f3"
    }
  ],

  // 注意：请求体里没有 senderAppId。
  // senderAppId 由 notify 鉴权中间件从 Authorization: Bearer grafana:grafana 中解析出来。
  // 本例中 senderAppId = "grafana"。
  "senderAppId": "grafana"
}
```

notify 接收后会生成三类数据库对象：

```jsonc
{
  "notifications": {
    // 新生成的 notification id。
    "id": "06b1a816-c73e-4804-991e-0347a2977fb9",

    // 来自请求体 idempotencyKey。
    "idempotencyKey": "grafana-direct-firing-400a50a6a9c85052",

    // 来自鉴权主体，不来自请求体。
    "senderAppId": "grafana",

    // 初始状态。
    "status": "pending"
  },

  "notification_recipients": [
    {
      "id": "68ab985e-fa3a-479d-91d7-e3c4e04cc551",
      "notificationId": "06b1a816-c73e-4804-991e-0347a2977fb9",

      // notify 把 recipient type/value 存在 params 里。
      "params": {
        "type": "feishu_user_id",
        "value": "ou_7fb2f2969dc389a1478aedeb680675f3"
      }
    }
  ],

  "delivery_tasks": [
    {
      "id": "ccf32f8e-0f92-40a9-ac74-aeae969ffd78",
      "notificationId": "06b1a816-c73e-4804-991e-0347a2977fb9",
      "recipientId": "68ab985e-fa3a-479d-91d7-e3c4e04cc551",

      // 来自 channels 的 key。
      "channel": "feishu_app",

      // 来自 notify 配置：
      // channels.feishu_app.provider = feishu-app-urgent
      "provider": "feishu-app-urgent",
```

## 7. 和中间转换接口的区别

旧方式：

```text
Grafana default webhook JSON
  -> POST /api/v1/grafana/webhook?channel=feishu_app&template=...&recipient=...
  -> notify 服务端把 Grafana 默认结构转换成 SendNotificationRequest
  -> /api/v1/notifications 内部等价处理
```

直连方式：

```text
Grafana ContactPoint payload.template
  -> 直接生成 SendNotificationRequest JSON
  -> POST /api/v1/notifications
```

直连方式的特点：

```jsonc
{
  // 优点：notify 服务端不需要维护 Grafana 专用转换接口。
  "lessServerAdapterCode": true,

  // 优点：字段映射都在 GrafanaContactPoint 里，变更时可以只改 CR。
  "mappingLivesInContactPoint": true,

  // 注意：Grafana 模板必须保证输出合法 JSON。
  // 因此推荐 coll.Dict + data.ToJSON。
  "mustRenderValidJson": true,

  // 注意：ContactPoint 需要理解 notify 原生请求结构。
  "contactPointKnowsNotifyRequestSchema": true
}
```

## 8. 当前配置建议

```jsonc
{
  // 建议修正。
  // 当前 53 实测 externalURL 是 http://localhost:3000/。
  // 飞书消息里如果展示这个链接，用户无法直接打开正确 Grafana。
  "grafanaExternalURL": "should-be-real-grafana-url",

  // 当前策略适合降低重复通知。
  // 如果业务希望 repeat_interval 每次都触发飞书加急，需要重新设计 idempotencyKey。
  "idempotencyStrategy": "grafana-<status>-<fingerprint>",

  // 当前接收人是单个 open_id。
  // 如果要多人接收，可以扩展 recipients 数组。
  "recipientStrategy": "single-feishu-open-id-from-secret",

  // 加急类型不是 contact point 控制的。
  // 它由 notify provider 配置决定，例如 app、sms、phone。
  "urgentTypeSource": "notify providers.feishu-app-urgent.urgentType"
}
```
